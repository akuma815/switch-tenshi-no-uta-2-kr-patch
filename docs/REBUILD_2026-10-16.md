# Switch판 최종 패치 재빌드와 삭제 검토 — 2026-10-16

## 현재 판정

이 문서는 원본과 Git에서 최종 배포의 **자산을 재현**하는 절차다. 게임 폴더는 이번 요청에서 삭제하지 않는다. 최종 판정과 실제 검증 수치는 `rebuild_verification_2026-10-16.json` 및 최신 인계를 따른다.

초기 공개 저장소에는 매뉴얼·폰트·일부 그래픽 입력과 배포 당시 교체 계획이 빠져 있었다. 현재 번역 원장은 배포 당시와 일부 문장이 다르므로 그대로 보존하고, 기존 최종본의 교체 계획을 `assets/release_plans/`에 별도로 동결했다. 기본 재현 빌드는 이 계획을 사용한다. `-CurrentTranslations`는 원장을 다시 반영하는 개발용 분기이며 기존 배포와 동일하다는 뜻이 아니다.

## 보완한 입력

- `assets/fonts/`: Galmuri11-Condensed, Galmuri9, Noto Sans CJK KR. 원문 OFL은 `licenses/`에 있으며 폰트 원래 이름을 유지한다.
- `assets/manual_binary_deltas/`: 직접 보유한 원본 Texture2D와 조합해 최종 매뉴얼 자산을 복원하는 VCDIFF. 원본 추출 그래픽이나 편집 PNG 전체를 넣지 않았다. 복원 전에 원본·패치 해시를, 복원 후 결과 해시를 검사한다.
- `assets/release_plans/`: 배포 당시의 대사·비주얼신·UI·선택 화면 교체 계획. 번역 원장 자체는 수정하지 않았다.
- `config/rebuild_inputs.json`: 지원 NSP·업데이트 및 원본 Paks 해시. `config/release_payloads.json`: 동결한 배포본의 자산별 해시.
- 외부 도구 경로와 원본 Paks 경로를 인자로 받는 빌드 진입점. 에뮬레이터 모드 폴더에 자동 배포하지 않는다.
- 2편에는 카드 글꼴 아틀라스·관련 편집 스크립트·번역표와 1편에 의존하던 폰트 메트릭 스크립트를 추가했다. 원본 카드 텍스처와 Track02.iso는 직접 보유한 원본에서 다시 추출한다.

**2편 번역 영상:** Eden 모드의 v1.5와 동일한 영상 10개를 원본 영상 기반 차분으로 `assets/video_deltas/`에 보관했다. 지원 원본과 Git 차분으로 정확한 MP4 바이트를 복원하며 기존 릴리즈 다운로드는 필요 없다. 자막 편집 원본과 인코딩 명령은 확인하지 못했으므로 다시 인코딩하는 절차와는 구분한다. [영상 보존·복원 안내](VIDEO_RECOVERY_2026-10-16.md). MP4·Track02.iso·원본 자산·NSP·키는 Git에 올리지 않는다.

## 준비와 원본 추출

Python 3.12.10과 `requirements.txt`의 버전에서 검증했다. `retoc 0.1.5`, `repak 0.2.3`, xdelta3 및 hactoolnet 실행 파일과 사용자가 보유한 키셋은 외부에서 지정한다. 실행 파일은 Git에 포함하지 않으며 `config/toolchain_sha256.json`에 이번 환경을 기록한다.

```powershell
python -m pip install -r requirements.txt
python -X utf8 translation/scripts/extract_switch_paks.py --base-nsp '원본.nsp' --update-nsp '업데이트.nsp' --keyset 'prod.keys' --hactoolnet 'hactoolnet.exe' --output '소스 체크아웃 밖의 비공개 추출 폴더'
```

실제 지원 파일명·크기·해시는 `config/rebuild_inputs.json`을 확인한다. 이 세션의 입력은 `H:/ryujinx/Roms`의 해당 본편과 `H:/ryujinx/Update`의 v1.0.1이다. 두 편 모두 본편과 업데이트 적용 후의 빌드 대상 Paks 5개가 바이트 단위로 같았다.

추출 폴더에는 티켓·개인 키 파일·원본·도구 로그가 만들어지므로 비공개로 둔다. 스크립트는 키 값을 출력하지 않으며 저장소 안으로 원본을 추출하는 것을 거부한다.

## 최종 자산 재빌드

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File translation/scripts/build_reproducible.ps1 -SourcePaks '추출 폴더/romfs_updated/Emulator_Tenshinouta/Content/Paks' -RetocPath 'retoc.exe의 절대 경로' -RepakPath 'repak.exe의 절대 경로' -XdeltaPath 'xdelta3.exe의 절대 경로'
```

원본 매뉴얼 차분·폰트·2편 카드/영상 입력을 먼저 복원하고 `translation/patch_P/`에 패치를 빌드한다. 그 뒤 IoStore의 모든 자산과 UFS 파일을 동결한 배포의 해시와 대조한다. 단순히 파일이 생성된 것만으로 성공 처리하지 않는다. 결과는 `translation/input_cache/latest_rebuild_verification.json`과 `qa/rebuild_*/verification.json`에 남는다.

컨테이너 조립 순서/메타데이터 차이로 `.ucas/.utoc/.pak` 전체 해시는 달라질 수 있다. 검증 원장에서는 **최종 컨테이너 바이트 동일성**과 **내부 자산 바이트 동일성**을 나누어 표시한다. 원래 배포 압축 파일 자체가 필요하면 기존 GitHub 릴리즈의 고정 파일을 사용한다. 이 세션에서 전체 플레이·실기·새 장면 시각 검수는 하지 않았다.

## 보존·삭제 범위

최종 패치 자산 재현과 편집 프로젝트 전체 복원은 다르다. 이 절차는 기존 매뉴얼의 cooked 자산을 복원하며 원래 편집 PNG/레이어 파일까지 복원하지 않는다. 과거 QA·캐시·중간 시도도 모두 Git에 있다는 뜻이 아니다. 삭제 전 별도 작업 기록 백업과 최신 인계를 확인한다. `Games/Tenshi no Uta II - Datenshi no Sentaku (Japan)` PC엔진판은 이번 범위 밖이다.

**다음 행동 하나:** 새 원격 체크아웃에서 지원 원본·명시한 외부 도구로 재빌드하고, 최신 영상 복원 및 전체 자산 검증 원장과 비교한다.
